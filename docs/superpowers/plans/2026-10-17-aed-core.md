**Goal:** Build the Lead's part of the AED placement optimizer: the shared interfaces, a stub campus, the coverage model, ILP, greedy, swap, Monte Carlo and sensitivity, plus every results CSV the other three teammates consume. **Architecture:** Plain-function modules joined by one `Instance` dataclass (numpy arrays). The `Instance` and `Params` are turned into a sparse `Coverage` (rows = cell × period × time band, columns = sites), and every solver consumes `Coverage`. All solvers report lives saved through the same `evaluate` function.

**Tech Stack:** Python 3.11, numpy, scipy ≥ 1.9 (`scipy.optimize.milp`, HiGHS), matplotlib, pytest.

**Spec:** `docs/superpowers/specs/2026-10-17-aed-placement-design.md`

## Review Focus

1. **Budget = 0 (K = 0):** solvers return only the existing AEDs with lives = `evaluate` of that set, without crashing. → Task 6 `test_zero_budget`, Task 7 `test_greedy_zero_budget`.
2. **A period where every site is locked:** that period contributes 0 and nothing errors. → Task 5 `test_all_closed_period`.
3. **A cell with no site within `max_tau_s`:** it produces no coverage rows; nothing errors. → Task 5 `test_unreachable_cell`.
4. **`ems_response_s` at or below the first band edge:** all benefits are 0, so the coverage has 0 rows and solvers return lives = 0. → Task 5 `test_ems_faster_than_all_bands`, Task 6 `test_empty_coverage`.
5. **Budget larger than the total cost of all sites:** solvers select every site and do not loop or fail. → Task 7 `test_budget_exceeds_all`.

- Test: `tests/test_coverage.py`

**Interfaces:**
- Consumes: Tasks 1, 2 and 4.
- Produces:
  - `@dataclass class Coverage`: `A: scipy.sparse.csr_matrix` (R × J, 0/1), `weights: np.ndarray` (R,), `row_cell`, `row_period`, `row_band: np.ndarray` (R,) int, `site_cost: np.ndarray` (J,), `site_existing: np.ndarray` (J,) bool, `n_periods: int`.
  - `build_coverage(inst: Instance, tau: np.ndarray, params: Params) -> Coverage`. Uses the **incremental form** from spec §5: with `(edges, b) = band_benefits(params)` and `Δb_k = b_k − b_{k+1}` (b past the last band = 0), there is one row per (i, p, k) with `λ_ip·Δb_k > 0` that has at least one site j with `tau[i,j] ≤ min(edges[k], max_tau_s)` and `site_open[j,p]`. Its row in A marks those sites and its weight is `λ_ip·Δb_k`. Covered rows are summed and no Σ_k ≤ 1 constraint is needed, because the sets are nested in k and the sum telescopes to `λ_ip·b_{k*}` for the fastest band k*.
  - `@dataclass class Solution`: `x: np.ndarray` (J,) bool, `lives: float`, `method: str`, `runtime_s: float`, `mip_gap: float | None = None`.
  - `evaluate(cov: Coverage, x: np.ndarray) -> float` = `weights[(A @ x.astype(float)) >= 1].sum()`.
  - `evaluate_by_period(cov: Coverage, x: np.ndarray) -> np.ndarray` of shape (P,).
  - `pipeline.build(seed: int = 0, params: Params | None = None, **gen_kwargs) -> tuple[Instance, Coverage]`.

def brute_lives(inst, tau, p, x):
    """Direct spec formula: Σ_ip λ_ip · b(fastest open selected site)."""
    edges, b = band_benefits(p); total = 0.0
    for i in range(inst.n_cells):
        for q in range(inst.n_periods):
            ok = x & inst.site_open[:, q] & (tau[i] <= p.max_tau_s)
            if ok.any():
                t = tau[i, ok].min(); k = np.searchsorted(edges, t)  # first edge ≥ t
                if k < len(b): total += inst.cell_rate[i, q] * b[k]
    return total

Formulation for `scipy.optimize.milp`: variables `[x (J) binary, z (R) continuous in [0,1]]`; minimize `−weights·z`; constraints `z_r − Σ_j A_rj x_j ≤ 0` (sparse block `[−A | I]`, upper bound 0), `site_cost·(x ∧ ¬existing) ≤ budget`; bounds `x_j ∈ [1,1]` for existing sites and `[0,1]` otherwise. When R = 0, skip the solve and return the existing set only.

**Interfaces:**
- Consumes: `Coverage`, `Solution`, `evaluate`.
- Produces: `solve_greedy(cov: Coverage, budget: float) -> Solution` with `method="greedy"`. Start from the existing sites and repeatedly add the affordable site with the largest `marginal_gain / cost` (lazy evaluation with a max-heap of stale upper bounds; marginal gain = sum of weights of rows that are not yet covered and that the site covers). ### Task 10: Monte Carlo uncertainty and one-at-a-time sensitivity

**Files:**
- Create: `aed/uncertainty.py`, `experiments/uncertainty.py`
- Test: `tests/test_uncertainty.py`

**Interfaces:**
- Consumes: `generate_instance`, `travel_time_matrix`, `build_coverage`, `solve_greedy`, `solve_ilp`, `evaluate`, `Params`, `RANGES`, `metres_to_latlon`.
- Produces:
  - `GEN_KWARGS: dict = {}`: a module-level constant passed to `generate_instance`, so tests can shrink the campus.
  - `sample_scenario(inst: Instance, base: Params, rng: np.random.Generator) -> tuple[Instance, Params]`: every key of `RANGES` drawn uniformly in its range (via `dataclasses.replace`); `cell_rate` × one factor from U(0.7, 1.3); 10% of non-existing sites (rounded, at least 1) each get `site_open` flipped for one random period. Returns copies and leaves the input unchanged. Positions never change, so site frequencies are comparable across scenarios.
  - `@dataclass class MCResult`: `lives_fixed: np.ndarray` (n,) (the base-case ILP placement evaluated under each scenario: how well our plan holds up), `lives_reopt: np.ndarray` (n,) (greedy re-optimized per scenario), `site_freq: np.ndarray` (J,) (share of scenarios whose re-optimized placement includes each site).
  - `monte_carlo(seed: int, budget: float, n: int = 500, rng_seed: int = 0, base: Params | None = None) -> MCResult`.
  - `@dataclass class OATRow`: `param, low_value, high_value, lives_at_low, lives_at_high, base_lives`.
  - `oat_sensitivity(seed: int, budget: float, base: Params | None = None) -> list[OATRow]`: for each key of `RANGES`, set it to its low then its high value (others at base), re-solve with `solve_ilp`, and record lives; sorted by `|lives_at_high − lives_at_low|`, largest first.
  - `experiments/uncertainty.py --seed 0 --n 200 --out results` writes `mc_kcurve.csv` (K = 0, 5, …, 30; `mean, p5, p95` of `lives_fixed`), `site_freq.csv` (at K = 10, lat/lon via `metres_to_latlon`) and `oat.csv` (at K = 10), each with exactly the mock headers.
